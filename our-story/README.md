# 우리라는 이야기

독립적인 가족 아카이브 UI. 배포 경로: `/mashimaru/our-story/`.

## 현재 범위

홈, 실제 Leaflet 지도, 국내/세계 보기, 여행 상세, 여행/성장 예시 기록 추가·수정·삭제, 여행 검색/연도, 성장 대상/나이/연도/주제 필터, 성장-여행 연결, 갤러리, 버킷리스트 추가·체크·삭제. 모바일은 지도 핀 선택 시 닫을 수 있는 하단 시트를 사용한다.

**공개 UI이며 완성된 가족 계정 서비스는 아니다.** 여행·성장 예시는 허구와 Unsplash 스톡으로 구성된다. 갤러리의 NAS 사진 탭은 별도 연결 정보를 입력한 기기에서 NAS API를 조회한다. 기존 API는 읽기 전용이며 새 관리 API는 NAS 쓰기 승인/설치 이후 업로드·휴지통을 지원한다. 인증 정보나 실제 사진은 저장소에 포함하지 않는다. 예시 기록은 메모리에서만 유지되며 새로고침 시 초기화된다. 사진 다운로드·스크롤 자동 미리보기·가족 공통 홈 대표 사진을 제공한다. 업로드·휴지통 UI는 API 지원 여부에 따라 활성화된다. 모든 사용자 입력은 HTML escape 또는 textContent로 렌더링한다. 사용자가 연결 기억을 선택하면 주소·토큰 또는 만료 시각이 있는 API 세션을 AES-GCM으로 암호화하여 이 기기의 IndexedDB에 보관한다. 비밀번호·사진 파일은 영구 저장하지 않는다. 직접 고른 홈 사진의 경로/이름과 앨범 연결은 업데이트된 NAS의 별도 설정 볼륨에 공통 저장하며, 기존 기기별 암호화 설정은 최초 이관에 사용한다. 실제 비밀을 GitHub나 localStorage에 넣지 않는다. noindex는 접근 제어가 아니다. NAS 연결 방법과 단계별 한계는 `docs/NAS-CONNECT.md` 참고.

## 실행

빌드 및 npm 설치 불필요. 저장소 루트에서 `python3 -m http.server 8000` 후 `http://localhost:8000/our-story/` 접속. ES module이므로 file://로 열지 않는다. 구문 검사: `node --check our-story/app.js`, `node --check our-story/data.js`.

## 파일 경계와 다음 단계

- `index.html`: 공통 탐색, 예시 안내, 모달, 접근성 골격.
- `style.css`: 크림/아이보리 디자인 토큰과 600/850px 반응형.
- `data.js`: API와 분리된 예시 데이터. UI 검증용이며 저장소 역할을 대신하지 않는다.
- `nas-client.mjs`: 기존/관리 API 계약, HTTPS 목적지 검증, 인증, 타임아웃, 응답 크기 제한.
- `nas-gallery.js` / `nas.css`: 실제 NAS 사진 탭, 연결 모달, 폴더/페이지 탐색, 인증된 Blob 미리보기 및 메모리 정리 및 기억된 연결 복원.
- `nas-vault.mjs`: 비추출형 Web Crypto 키와 AES-GCM 암호문을 IndexedDB에 원자적으로 저장/삭제한다. 동일 origin 스크립트에 대한 보안 격리 수단은 아니다.
- `app.js`: 라우팅, 화면 렌더링, 메모리 편집. 입력값 길이/필수/숫자 범위/날짜 순서를 검증한다.
- `assets/`: 실제 가족사진이 아닌 로컬 스톡 자산.
- `vendor/`: Leaflet 1.9.4와 라이선스. 지도의 배경 타일만 외부 요청한다.

2차 구현은 프런트 → HTTPS 앱 서버 → DB / 읽기 전용 NAS 어댑터로 분리한다. 여행/성장 저장소와 NAS 원본 조회는 별도 서비스 경계로 유지한다. 현재 단계는 기존 토큰 서버를 변경하지 않는 브라우저 직접 조회이며, 아래 앱 서버/프록시는 후속 설계다. 앱 서버는 가족별 멤버십/초대/관리자 역할을 매 요청 검사하며 HttpOnly, Secure, SameSite 쿠키 기반 세션, 로그인 속도 제한, CSRF 방어, 비밀번호 해싱 및 세션 만료/철회를 구현해야 한다. 브라우저에 NAS 토큰을 전달하지 않는다. 실제 사진은 서버 인증 후 읽기 전용 프록시 또는 짧은 만료 URL로 제공한다. GitHub Pages는 정적 UI만 호스팅할 수 있으므로 가족 서비스 전환 전 별도 서버 운영과 접근 제어가 필수다.

기존 `nas-photo-test/`와 NAS 실행 환경은 수정하지 않았다. 코드 조사 기준 API에는 `/api/login`, `/api/setup`, `/api/logout`, `/api/status`, `/api/list`, `/api/image`가 있으나 NAS 실행 버전과 이미지/인증 동작은 검증하지 않았다. 기록 저장 API, 사용자별 가족 권한, 썸네일 생성은 없다. 문서의 토큰 설명과 현재 코드 사이에도 버전 차이가 있다. Quick Tunnel은 테스트 전용이며 현재 앱은 사용자가 입력한 Quick Tunnel HTTPS origin만 호출할 수 있다. NAS 배포/볼륨/권한/터널 변경은 별도 승인 이후 진행한다.

향후 데이터 모델은 여행 시작/종료일·국가/도시·좌표·동행·대표/추가 미디어·작성/수정 시각, 성장 대상·기록일·카테고리·미디어·연결 여행·측정치, 미디어 참조 ID와 작성자 ID를 갖춘다. 생년월일 입력 전 실제 나이는 계산하지 않는다. 가족별 후기, 영상, 월 필터, 영구 DB, 백업, 초대/로그인/권한은 미구현이다. 사진 업로드·휴지통 API는 `nas-service/`에 구현했지만 실제 NAS 설치는 별도 단계다.

## 후속 점검

사용자 인터랙션 참고 기준은 `AGENTS.md`에 유지한다. 하트 핀은 Leaflet 위치 transform과 분리한 SVG로 교체했다. NAS 연동의 구현 필요 사항과 로컬 검증 범위는 `docs/NAS-INTEGRATION.md`, 계약 테스트는 `tests/test_nas_contract.py`에 있다. 실제 NAS에 연결한 것으로 간주하지 않는다.

## 사진 관리 확장 (2026-11-13)

미리보기 12장 제한 제거, 화면 근처에서 순차 로딩(동시 2개), 목록 100개 단위 자동 추가와 수동 더보기, Blob 캐시 최대 48개/64MB(현재 화면 항목은 유지)를 적용했다. 사진 총량을 제한하는 설정이 아니며 이전 위치로 스크롤하면 다시 불러온다. 연결 API에 썸네일이 있으면 이를 사용하고, 없으면 기존 원본 API를 사용한다. 다운로드는 기존 API에서 15MB, 새 API에서 128MB까지 지원한다. 홈 대표 사진 선택·앨범 폴더·이름 규칙은 업데이트된 NAS 서비스에서 가족에게 공유된다. 구버전 서버는 공통 저장을 지원하지 않으며 업데이트 안내를 표시한다.

새 NAS 서비스의 변경 범위와 설치/롤백은 `nas-service/README.md`, 소스 묶음은 `downloads/our-story-nas-service.zip`에 있다. 새 Docker 이미지 빌드용 workflow는 기존 workflow를 수정하지 않고 추가했다. 실제 NAS 원본·실행 환경을 변경한 것으로 간주하지 않는다.

## 메인 화면 자동 사진 (후속 수정)

NAS 연결 복원 시 홈을 실제 사진 모드로 바꾸고 대표 사진/사진 모음을 자동으로 채운다. 여행·성장앨범은 폴더 한 번 연결 후 하위 사진을 자동 조회한다. 기존 수동 대표 사진은 선택적 우선 설정이며 필수가 아니다. 실제 사진을 예시 기록·지도 핀·나이별 타임라인에 임의로 결합하지 않는다. 폴더 바인딩은 별도 암호화 DB에 이 기기에서만 보관한다. 사용법·미리보기 탐색 범위·실제 NAS 미검증 경계는 `docs/AUTO-ALBUMS.md` 참고.

연도별 하위 폴더가 같은 기본 이름과 숫자 접미사로 반복되면 **이름으로 모으기**를 사용한다. 기본 이름만 입력해 모든 연도의 일치 폴더를 모으며 기존 폴더 선택과 함께 지원한다. 사용법과 검색 한계는 `docs/NAME-RULES.md` 참고.

가족 설정 공유의 설치/이관/동시 수정/구버전 경계는 `nas-service/README.md`의 「가족 공통 설정 업데이트」를 따른다. 탐색 탭·연도 필터·예시 이야기 기록은 공유 설정이 아니다.
