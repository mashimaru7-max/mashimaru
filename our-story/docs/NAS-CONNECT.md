# NAS 사진 연결 — 기존 서버를 그대로 사용하는 읽기 전용 단계

## 사용 방법

1. `https://mashimaru7-max.github.io/mashimaru/our-story/#nas` 접속. 갤러리의 **NAS 사진** 탭이나 상단 **NAS 연결**에서도 진입 가능.
2. **NAS 사진 보관함 연결**을 누르고 기존 테스트에서 쓴 현재 유효한 `https://…trycloudflare.com` 주소와 **사진 조회 토큰**을 입력한다. DSM 관리자 비밀번호는 입력하지 않는다. 비밀 값은 채팅이나 GitHub에 보내지 않는다.
3. 연결 후 `/photo` 폴더를 탐색하고 사진을 눌러 확대한다. 상위 폴더·경로 이동·더 보기 지원. 자동 미리보기는 기본 OFF이며, 켜면 현재 폴더 첫 12장만 원본을 최대 2장씩 동시에 받아 축소 표시한다.
4. 종료 시 **연결 끊기**. 새로고침하거나 페이지를 떠나면 연결 정보를 다시 입력해야 한다. 같은 페이지 안의 홈/여행/성장 탭 이동은 연결을 유지한다.

사진 API를 이미 로그인 방식으로 바꾼 사용자만 연결 방식을 **사진 API 로그인 (설정한 경우)**으로 선택한다. 인증 실패 시 다른 방식으로 자동 전환하지 않는다. 설정 API `/api/setup`은 이 앱에서 호출하지 않는다.

## 연결 흐름과 경계

GitHub Pages의 브라우저 앱 → 기존 Cloudflare Quick Tunnel → 기존 NAS 사진 API → `/photo` 읽기 전용.

- 원본 업로드·삭제·이동·수정 기능 없음. API 요청은 목록/사진 GET 및 사용자가 로그인 방식을 고른 경우의 기존 login/logout POST뿐이다.
- 새 토큰이나 계정을 생성하지 않는다. 기존 NAS 서버, 컨테이너, 권한, 볼륨, 터널 설정은 변경하지 않았다.
- 사용자 입력 endpoint만 사용하며, HTTPS `*.trycloudflare.com` 단일 호스트의 origin만 허용한다. 사용자명/비밀번호 포함 URL·경로·query·fragment·비표준 포트는 거부한다. 리다이렉트 추적은 하지 않는다.
- 토큰은 Authorization 헤더에만 보낸다. 비밀번호는 명시적으로 선택한 로그인 요청 본문에만 보낸다. 브라우저 쿠키를 NAS 요청에 첨부하지 않는다.
- 토큰과 로그인 후 세션은 연결 중인 JS 메모리에만 보관한다. 폼의 비밀 입력값은 요청 시작/닫기 때 지운다. localStorage, sessionStorage, IndexedDB, 서비스 워커, 별도 로그 저장 없음. 브라우저 자체의 비밀번호 관리·확장 프로그램·개발자 도구에서의 노출까지 방지한다는 뜻은 아니다.
- 목록 경로와 사진 Blob URL도 이 기기의 메모리에만 유지한다. 폴더 이동/미리보기 해제/갤러리 이탈/연결 종료 시 필요 없어진 Blob URL을 해제한다. 연결 종료 및 401 응답 시 요청을 중단하고 목록/경로/이미지를 지운다. 늦게 도착한 응답으로 이전 연결이 복구되지 않도록 요청 세대를 검사한다.
- 서버 세션 모드 종료 시 기존 `/api/logout` 호출로 세션 철회를 시도하고, 네트워크 실패 여부와 무관하게 로컬 연결은 즉시 제거한다. 기존 토큰 모드는 서버 토큰 자체를 폐기하거나 변경하지 않는다.
- 목록은 한 번에 최대 100개, JSON 2MB, 사진 15MB 제한. 응답 본문 스트림을 읽는 동안에도 크기를 검사한다. 사진 MIME은 래스터 형식만 허용하고 SVG/HTML은 미리보기하지 않는다.
- 현재 페이지 CSP는 스크립트/연결 목적지를 제한하고 브라우저의 기본 form 전송을 차단한다. JavaScript가 동작하지 않을 때 인증 정보가 form query로 전송되는 것을 방지한다.

## 현재 한계

이 연결은 **기존 공유 토큰 기반 읽기 전용 연동 단계**다. 가족 구성원별 로그인·초대·권한, 앱 서버의 NAS 프록시, 여행/성장 기록 영구 DB는 아직 구현하지 않았다. 예시 데이터와 실제 NAS 사진은 탭으로 분리하며 NAS 사진을 예시 기록에 자동 삽입하지 않는다. 사진 GPS를 읽어 여행 핀을 자동으로 찍지 않는다.

Quick Tunnel은 임시 연결이므로 주소가 바뀌면 새 주소를 직접 입력해야 한다. 고정 HTTPS 주소, API의 썸네일 생성, HEIC 변환, 동영상/범위 요청, 사진을 여행/성장에 연결하는 영구 미디어 참조는 후속 작업이다. 썸네일 API가 없으므로 자동 미리보기는 원본을 받으며 모바일 데이터 사용량이 발생한다. 15MB 초과 사진은 오류를 표시한다.

소스 저장소의 `nas-photo-test/server.py`는 세션 로그인 방식이지만, 이전에 확인된 실제 NAS 설치본은 토큰 방식으로 연결했고 로그인 전환은 보류했다. 클라이언트가 둘을 명시적으로 구분하도록 했다. 실제 설치 버전은 원격 검증 전까지 단정하지 않는다.

## 오류 안내

| 표시 | 확인할 내용 |
| --- | --- |
| 인증되지 않음 (401) | 기존 사진 조회 토큰 / 선택한 인증 방식. 이미 연결된 세션이면 화면도 정리 후 재연결 필요 |
| 접근 불가 (403) | 기존 서버가 허용하는 웹 origin. 현재 Pages origin은 `https://mashimaru7-max.github.io` |
| 기능 없음 (404) | 잘못된 폴더·사진 경로, 또는 로그인 기능 없는 구형 서버에서 로그인 방식을 선택했는지 |
| 로그인 설정 미완료 (409) | 서버 로그인 설정 미완료. 앱이 서버 설정을 대신 변경하지 않음 |
| 크기 제한 (413 / SIZE) | 15MB 초과 사진. 원본을 수정하거나 축소 저장하지 않음 |
| 응답 지연 / 연결 불가 | NAS·기존 API·터널 실행 상태와 현재 URL. 만료된 터널이나 HTML 오류 응답을 연결 성공으로 처리하지 않음 |

## 검증

- `node --test our-story/tests/nas-client.test.mjs`: 18개 통과. URL/경로, 목적지/헤더, 토큰/세션 모드, 크기 제한, 동시 연결·취소·만료·시간 초과·오류 정리 검증.
- `python -B -m unittest discover -s our-story/tests -v`: 기존 API 계약 시험 12개 통과. 임시 파일/루프백 서버만 사용.
- 브라우저: 실제 UI의 연결 모달과 인증 방식 필드 전환 확인. 별도 미배포 QA fixture에서 폴더/빈 상태/403/15MB 오류, 100→101개 페이지 추가, 인증된 Blob 사진 표시, 첫 12장 미리보기, 미리보기 해제·401·연결 끊기 후 화면 정리 확인. 390px iframe 콘텐츠 375px/scrollWidth 375px 확인.
- QA fixture는 실제 가족사진이 아닌 스톡 사진과 가상 API 응답을 사용했으며 배포에 포함하지 않는다. 실제 NAS 원격 연결과 성능은 미검증이다.
