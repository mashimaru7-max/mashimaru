# NAS 연동 점검 — 2026-11-13

## 판정

현재 UI를 유지하며 NAS 연동을 확장할 수 있다. **현재 앱은 연결되어 있지 않으며, 현재 코드를 그대로 연결한다고 완성되는 상태는 아니다.** `app.js`는 정해진 로컬 스톡 사진 경로만 렌더링하고, 기록은 메모리 배열에서 관리한다. NAS용 미디어 공급자와 인증·영구 저장 계층을 실제 구현해야 한다.

## 저장소 조사에서 확인한 내용

| 영역 | 현재 상태 | 다음 구현 |
| --- | --- | --- |
| 웹 화면 | GitHub Pages 정적 화면 | 그대로 유지 가능 |
| 사진 목록 | 기존 `/api/list`, 로그인 세션 필요 | 로그인 서버 뒤에서 호출하는 읽기 전용 어댑터 |
| 사진 파일 | 기존 `/api/image`, 15MB 초과 거부 | 썸네일 및 큰 이미지 처리 별도 설계 |
| 사진 렌더러 | `assets/`의 고정 스톡 사진 4개 | 미디어 ID와 인증된 조회 경로를 받는 렌더러 |
| 기존 테스트 화면 | 입력받은 고정 토큰을 Bearer로 보냄 | 서버의 세션 로그인 방식과 정합성 확인 필요 |
| 기존 서버 인증 | 고정 사용자 한 명, 로그인 후 메모리 세션 | 가족 초대·구성원·역할·기록별 검사 없음 |
| CORS | `https://mashimaru7-max.github.io` 허용 | 현재 Pages origin과 일치. 다른 호스팅으로 이동 시 변경 승인 필요 |
| 기록 저장 | 서버 API 없음 | 사진 파일과 별도 DB 및 백업 |
| 동영상 | 사진 목록에서 제외 | 영상 제공 API와 브라우저 코덱/범위 요청 검증 필요 |
| HEIC/HEIF | 목록에 포함하지만 변환 없음 | 브라우저 표시를 보장할 수 없으므로 변환/대체 미리보기 |
| 외부 주소 | Quick Tunnel 임시 연결 | 고정 HTTPS 접속 경로와 인증을 별도 확정 |

CORS는 가족의 접근 권한을 대신하지 않는다. 서버 코드는 Origin 없는 GET도 거부하므로 새 앱 서버에서 NAS를 중계할 때도 해당 계약과 인증을 명시적으로 맞춰야 한다. 일반 `<img src="NAS주소">`는 이 API가 요구하는 Bearer 인증 헤더를 붙일 수 없다. 기존 테스트 UI는 인증된 fetch 결과를 Blob URL로 보여주지만, 새 실서비스에서는 가족 인증을 통과한 미디어 프록시 또는 짧은 만료 URL이 우선이다.

## 권장 구조

화면은 당분간 GitHub Pages에 유지하고, 가족 로그인·초대·접근 제어·여행/성장 DB를 담당하는 앱 서버를 분리한다. 앱 서버에서 NAS 읽기 전용 어댑터를 호출한다. NAS 원본 사진은 그대로 두고 기록에는 안정적인 미디어 참조만 저장한다. NAS 토큰·서비스 세션·비밀번호를 프런트 번들이나 GitHub에 넣지 않는다.

UI는 미디어 공급자 전환 후에도 유지할 수 있지만, 현재 고정 `img()` 함수를 대체하고 다중 미디어·조회 취소·지연 로딩·상태별 UI를 추가해야 한다. 읽기 전용 연결이 먼저 검증된 다음 썸네일/영상/DB 순으로 확장한다. 실제 DB를 붙이기 전에는 새로고침 시 초기화되는 체험 모드를 유지한다.

## 검증 범위와 한계

`python -B -m unittest discover -s our-story/tests -v` — 12개 통과.

저장소의 기존 서버 코드를 별도 Python 프로세스 메모리에 로드하고 임시 폴더와 루프백 HTTP 서버로 시험했다. 로그인 세션으로 목록/파일 조회, 인증 없음/고정 토큰 거부, 다른 origin 거부, 경로 탈출/외부 symlink 거부, 15MB 초과 거부, 로그아웃 후 세션 무효화, 미지원 영상/기록 저장 API를 확인했다. 실제 사진의 디코딩·HEIC·영상·대량 폴더 성능은 검증하지 않았다.

**실제 NAS에 설치된 코드 버전, 원격 URL, 네트워크, 인증 상태는 확인하지 않았다.** 저장소 코드와 NAS 설치본이 다를 수 있다. NAS 설정·실행 컨테이너·원본 사진·기존 nas-photo-test 파일은 변경하지 않았다.

## 호스팅 판단

GitHub Pages는 HTML/CSS/JS 정적 호스팅이므로 이 UI에는 적합하지만 서버 인증/DB를 직접 실행하지 않는다. Cloudflare Pages/Workers는 무료 범위의 대안이며 서버 요청은 별도 사용량 제한이 있다. 이전 자체로 가족 인증이나 NAS 연동이 완성되지는 않는다. 현재는 화면을 Pages에 유지하는 것이 변경 범위가 작다.
