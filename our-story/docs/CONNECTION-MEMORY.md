# 이 기기에서 NAS 연결 기억

2026-11-13 사용자 요청: 가족 로그인은 추후에 진행하고, 주소와 사진 조회 토큰을 매번 입력하지 않도록 저장한다. 공개 GitHub 저장소에 비밀 값을 넣는 대신 기기별 암호화 저장을 구현했다.

## 동작

- 연결 폼의 **이 기기에서 연결 기억**은 기본 ON이다. 유효한 API 목록을 받아 연결을 확인한 다음 저장한다.
- 저장 내용은 NAS HTTPS origin, 인증 방식, 토큰 또는 API 세션, 세션 만료 시각뿐이다. 비밀번호·사진·폴더/파일 경로·여행/성장 기록은 저장하지 않는다.
- 같은 브라우저에서 새로고침·페이지 재방문·새 탭 열기 시 저장 정보를 복호화하고 실제 API 인증 검증을 거친 뒤 연결 상태로 표시한다. 저장 데이터가 존재한다는 이유만으로 연결 성공을 표시하지 않는다.
- 저장 옵션을 끄면 메모리 연결만 사용하고 이전 저장 정보도 지운다. 비공개 모드나 저장 차단/용량 오류에서는 저장 실패 안내를 표시하며 현재 사진 조회는 유지한다.
- **연결만 끊기**는 이번 화면을 정리하며 기억한 정보를 유지한다. 다음 방문에 자동 재연결한다.
- **저장 정보 지우기**는 요청을 취소하고 화면의 사진·목록을 정리하며, IndexedDB의 암호문과 키를 함께 삭제한다. 다음 방문에도 자동 연결하지 않는다.
- 터널 주소가 바뀌면 연결 설정에서 주소만 수정할 수 있다. 저장된 토큰을 다시 입력할 필요가 없고, 새 주소의 API 연결이 성공한 뒤 업데이트한다. 요청 대상은 사용자가 고른 HTTPS Quick Tunnel origin으로 한정하며 리다이렉트를 허용하지 않는다.
- 토큰 인증 거부(401)·API 세션 만료·변조/손상된 저장 정보는 삭제하고 재입력을 안내한다. 일시적인 네트워크/터널 오류에서는 기억한 정보를 유지하여 재시도한다.

이전 배포 버전은 메모리만 사용했으므로 그때 입력한 토큰을 새 버전이 복구할 수 없다. 업데이트 후 최초 한 번은 다시 연결해야 한다. 이후 브라우저 사이트 데이터를 삭제하거나 시크릿 모드/다른 브라우저/다른 기기를 사용하면 다시 입력해야 한다.

## 저장 구현과 한계

`nas-vault.mjs`는 Web Crypto AES-256-GCM, 매 저장 시 새 랜덤 IV와 비추출형 암호키를 사용한다. IndexedDB에는 버전·CryptoKey·IV·암호문만 들어가며 평문 토큰은 들어가지 않는다. 쓰기는 트랜잭션 완료를 기다리고, 저장과 삭제 요청을 직렬화하여 늦게 완료된 저장이 삭제를 되돌리지 못하게 한다.

암호키도 같은 브라우저의 같은 origin에 보관된다. 따라서 비추출형 키와 암호화는 **동일 origin에서 실행되는 악성 스크립트/XSS/확장 프로그램으로부터 토큰 사용을 완전히 차단하지 않는다**. GitHub Pages의 여러 프로젝트는 같은 origin을 공유할 수 있다. 이는 서버의 가족 로그인이나 HttpOnly 세션을 대신하지 않는, 사용자가 요청한 기기별 편의 기능이다. 실제 비밀을 Git에 커밋하거나 앱 번들에 넣지 않는다.

## 검증

- JS 테스트 36개 통과: 기존 API 클라이언트 18개, 저장/복원 연동 9개, 암호화 저장소 9개.
- 암호문에 평문 토큰이 포함되지 않음, 키 raw export 불가, 새 IV, 저장소 인스턴스 교체 후 복원, 변조 거부, 삭제와 동시 저장 경합, 저장 실패를 검증했다.
- 브라우저 실제 IndexedDB/structured clone을 사용한 미배포 fixture에서 새 문서·새로고침·새 탭 자동 복원과 저장 완료 후 삭제·재방문 비연결 상태를 확인했다. QA는 별도 DB 이름과 가상 API/가짜 토큰을 사용했으며 실제 NAS 비밀이나 사진은 사용하지 않았다.
- 사용자 기기에 이미 입력되어 있던 토큰에는 접근하지 않았다. 실제 NAS 인증 유지와 Quick Tunnel 가용성은 사용자 환경에서 추가 확인할 사항이다.
